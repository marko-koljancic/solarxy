Hierarchy build: the worker against the main thread

Builds an acceleration structure over roughly a million triangles twice: once in a worker and once on the main thread, with a task loop running throughout. The number that matters is the longest the main thread went without being able to run anything, because a render loop that cannot get a task cannot draw a frame. A worker build should cost it a task; a main-thread build should block it for the whole build, which is the reason the worker exists.

The square below is driven by an animation frame, for a human watching: it keeps moving during the worker build and freezes during the main-thread one. It is deliberately not the instrument, because an automated tab never gets one.

Build with the probe on: bash crates/solarxy-web/build-wasm.sh crates/solarxy-web/smoke/pkg --features pt-probe
